# Runtime improvement cycles

`watch dashboard` shows the current cycle stage, reason, completed reviews, measured runtime score and accepted deployments. `watch events --follow`, `watch guard` and `watch report` expose the same evidence. Existing `watch --dashboard`, `--guard`, `--report` and root `--follow` forms remain compatibility aliases. `status improvements` uses the same dashboard data.

A completed cycle can conclude that no change is justified. Zero accepted deployments is not the same as zero completed cycles. Missing scores are unavailable rather than zero, and a measured baseline without an accepted deployment is `BASELINE_ONLY`.

`configuration runtime-improvement` inspects controls. Its `--enabled`, `--auto-deploy` and `--interval-seconds` switches control the bounded runtime worker; `product improvements list|enable|disable` controls real registered improvement products. `product list` retains its original registry purpose.

The existing supervisor routes enabled runtime and specification products independently. A disabled specification product cannot keep requesting editorial improvements. Local baseline measurement does not require a native executor, while proposals require ordinary and shared admission. No failure/quota bypass is used by runtime proposals or diagnostic preflight.

The current automatic scope covers selected planning/feedback helper bodies only. Owner purpose, normative product, interfaces, imports, authority, transport, accounting, evaluator, tests and controllers are frozen outside that scope. A candidate needs source-bound private functional/robustness/determinism checks, public regression checks, the full isolated core/trial suite, unchanged owner thresholds and complete attributable local proposal provenance. Neither a caller's score nor a remote signature authorizes deployment.

Deployment queues through the same supervisor. It drains existing work, journals original files and metadata, checks fresh owner controls, publishes scoped changes, verifies the installed result, updates every source-pin alias and recovery snapshot, and reloads the controller. Failure restores scoped files while preserving unrelated work. Unexpected concurrent source changes block automatic rollback instead of overwriting the owner.

`api protocols` describes the canonical operation core and explicit CLI, typed API, MCP, A2A and peer bindings. These share validation and authority semantics where applicable; unsupported streaming, delivery and lifecycle semantics are stated explicitly. Protocols are not universally interchangeable.

The runtime score covers declared test contracts, not general product worth. Finite tests, provisional thresholds and bounded automatic scope cannot establish a perfect allowance/prohibition balance, all semantic behavior, real-user benefit, market fit or indefinite maintenance-free operation. A 100-point bounded baseline may legitimately yield no further score-qualified work. Widening the evaluator or automatic scope requires a separate owner-maintained version and a new compatible cohort.
